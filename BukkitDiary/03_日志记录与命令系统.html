日志记录：从 sout 到 Logger

众所周知，Minecraft客户端和服务端都是基于Java实现的，并且要在JVM虚拟机上运行。这就决定了绝大多数情况下有关Minecraft的一切都要受到Java语言的管理控制。当我们试图发送一些消息，或者服务器处理一些事件，通常都可以被Logger日志系统控制。根据Java语法，我们可以使用System包中的"out"方法输出内容，并且使用println("");方法将这些输出内容打印。例如：

示例
System.out.println("Hello MeT!");

这样就可以在被调用时在控制台中打印"Hello MeT!"了！这个方法可以在IDEA中输入"sout"直接Tab补全。是不是很方便？但是不要着急，这样做有一个弊端：sout只是单纯的输出一条不能称得上日志的文本。如果服务器关闭，该方法不会留下任何执行记录，这就导致了我们在处理较复杂的Java程序或者Bukkit插件时难以掌握运行的状态。

BukkitAPI为我们解决了这个问题！还记得我们创建主类时拓展的JavaPlugin吗？没错，Bukkit提供了一个叫做Logger的方法：

JavaPlugin.java - getLogger()
@NotNull
@Override
public Logger getLogger() {
    return logger;
}

这个方法允许我们使用不同等级的日志记录，这样在关闭服务器时就会在日志文件里保存由这些日志方法输出的文本信息：

日志级别对比
System.out.println("没有日志功能的sout输出");

Bukkit.getLogger().info("调用方法");
getLogger().info("INFO 信息级别日志");
getLogger().warning("WARNING 警告级别日志");
getLogger().severe("ERROR 错误级别日志");
Tips: 使用 Logger 的好处在于日志会自动保存到服务器的 logs 文件夹中。通过 severe 级别输出的错误在控制台中通常会以红色显示，非常醒目。

其实这些有关日志记录本质上是对于服务器或者玩家操作记录的保存方式，同时这也是反应命令系统有效运行的最直接方式之一。

从原版命令到插件命令

而对于Minecraft，在原版MC中已经支持了一些简单的原版命令。例如/gamemode <游戏模式> [玩家ID]可以切换指定玩家的游戏模式；或者/tp 玩家、/tp <x> <y> <z>可以传送至指定坐标位置。亦或者在官方服务端中可以使用/op和/deop切换玩家的管理员状态，我们只要在聊天栏中输入"/"即可查看所有可用的命令。但是我们也很容易发现：很多大型服务器都有他们自己的玩法和命令。插件是如何做到这种事情的？这就要提到我们本节重点问题：

实战：生成实体命令 (SpawnEntityCommand)

我们应当在onCommand方法中设计此命令执行的具体逻辑，在onTabComplete方法中设计Tab补全逻辑。由于命令的处理是一套系统逻辑，如果单独拆分分析，结论会是Java基本原理，相对不符合我们掌握命令系统的具体需求。所以我们直接给出成品并在下文以Q/A的方式进行分析：

SpawnEntityCommand.java
package top.brmc.bukkitplatform.diaryplugin.command;

import org.bukkit.Bukkit;
import org.bukkit.ChatColor;
import org.bukkit.Location;
import org.bukkit.command.Command;
import org.bukkit.command.CommandExecutor;
import org.bukkit.command.CommandSender;
import org.bukkit.command.TabCompleter;
import org.bukkit.entity.EntityType;
import org.bukkit.entity.Player;
import org.jspecify.annotations.NonNull;

import java.util.ArrayList;
import java.util.List;

public class SpawnEntityCommand implements CommandExecutor, TabCompleter {

    @Override
    public boolean onCommand(@NonNull CommandSender sender, @NonNull Command command, @NonNull String label, String[] args) {

        if (!(sender instanceof Player)) {
            sender.sendMessage("只有玩家可以执行此命令!");
            return true;
        }

        if (args.length < 2)
            return false;

        Player player = (Player) sender;
        EntityType entityType;

        try {
            entityType = EntityType.valueOf(args[0].toUpperCase());
        } catch (Throwable t) {
            sender.sendMessage(ChatColor.RED + "没有这种实体 '" + args[0] + "'!");
            return true;
        }

        if (!entityType.isAlive() || !entityType.isSpawnable()) {
            sender.sendMessage(ChatColor.RED + entityType.getName() + " 这个实体无法生成!");
            return true;
        }

        if (args.length == 4) {
            int x = this.parseNumber(args, 1);
            int y = this.parseNumber(args, 2);
            int z = this.parseNumber(args,3);

            if (x == -1 || y == -1 || z == -1) {
                sender.sendMessage(ChatColor.RED + "请检查你输入的坐标, XYZ 必须是数字类型! 例如: " + String.join(" ", args));
                return true;
            }

            Location location = new Location(player.getWorld(), x, y, z);
            player.getWorld().spawnEntity(location, entityType);

        } else if (args.length == 2) {
            Player targetPlayer = Bukkit.getPlayer(args[1]);

            if (targetPlayer == null) {
                sender.sendMessage(ChatColor.RED + "玩家 '" + args[1] + "' 不在线!");
                return true;
            }

            targetPlayer.getWorld().spawnEntity(targetPlayer.getLocation(), entityType);
        }

        return false; // false = 玩家需要查看Usage用法
    }

    private int parseNumber(String[] args, int index) {
        try {
            return Integer.parseInt(args[index]);
        } catch (Throwable t) {
            return -1;
        }
    }

    @Override
    public List<String> onTabComplete(@NonNull CommandSender sender, @NonNull Command command, @NonNull String alias, String[] args) {

        if (!(sender instanceof Player))
            return new ArrayList<>();

        List<String> completions = new ArrayList<>();
        Player player = (Player) sender;

        switch (args.length) {
            case 1:
                for (EntityType entityType : EntityType.values())
                    if (entityType.isSpawnable() && entityType.isAlive()) {
                        String name = entityType.toString().toLowerCase();
                        if (name.startsWith(args[0]))
                            completions.add(name);
                    }
                break;

            case 2:
                for (Player onlinePlayer : Bukkit.getOnlinePlayers()) {
                    String name = onlinePlayer.getName();
                    if (name.startsWith(args[1]))
                        completions.add(name);
                }
                completions.add(String.valueOf(player.getLocation().getBlockX()));
                break;

            case 3:
                completions.add(String.valueOf(player.getLocation().getBlockY()));
                break;

            case 4:
                completions.add(String.valueOf(player.getLocation().getBlockZ()));
                break;
        }

        return completions;
        // 如果 return null; 等同于设置返回在线玩家列表为空，等于返回空集合，也就是等同于 new ArrayList<>()
    }
}

Q & A 解析

Q1：这个类为什么要 implements CommandExecutor, TabCompleter？

这两个接口是 Bukkit 插件开发中的标准接口。
CommandExecutor：表示该类能处理命令执行逻辑，通过实现 onCommand() 方法。
TabCompleter：用于提供命令的输入自动补全，通过实现 onTabComplete() 方法。
Java 中用 implements 表示一个类去实现接口中定义的抽象方法。

Q2：为什么 @Override 注解要写在方法上？

@Override 告诉编译器这个方法是对接口中方法的重写（override）。这样当方法签名写错时，编译器会报错，能提前发现逻辑错误。

Q3：@NonNull 是什么？

@NonNull 来自 org.jspecify.annotations 库，表示参数或返回值不允许为 null，这是一个静态分析注解，用来防止空指针错误。

Q4：if (!(sender instanceof Player)) 作用是什么？

instanceof 是 Java 的类型检查关键字，判断对象是否某个类型的实例。
这里是判断命令发送者是不是玩家（Player），以防止控制台执行玩家命令。如果不是玩家，就直接返回提示。

Q5：Player player = (Player) sender; 为什么可以强制转换？

因为上面用 instanceof 检查过，当条件成立时 sender 一定是 Player 对象，因此强转安全。

Q6：if (args.length < n) 检查什么？

检查命令参数数量是否足够。如果参数不符合要求，会返回 false，Bukkit 会自动显示命令的帮助信息（Usage）。

Q7：为什么要检测 !entityType.isSpawnable() 和 !entityType.isAlive()？

Minecraft 中有些实体（如粒子、天气、方块）无法生成到世界，这样的实体类型虽然存在，但不应创建。此检查属于有效性验证，防止运行错误或游戏崩溃。

Q8：命令中为什么要用 .equals() 或 .startsWith() 来匹配字符串？

.equals() 比较两个字符串是否完全相同。
.startsWith(prefix) 用于前缀匹配，比如输入部分字符串时可以匹配所有以该字符串开头的项（用于 tab 自动补全）。
Java 不用 == 比较字符串内容，因为 == 比较的是对象引用。

Q9：try...catch (Throwable t) 有什么作用？

捕获可能的异常。如果用户输入了不存在的实体名，EntityType.valueOf() 会抛出异常，这里捕获后提示玩家"没有这种实体"。Java 异常机制能防止程序在错误输入时崩溃。

Q10：私有方法 parseNumber() 为什么用 try-catch？

Integer.parseInt() 转换非数字时会抛出 NumberFormatException。catch 块中返回 -1 表示非法值。这是一种容错处理方式，把异常输入转为可控制的数值，用于后续判断。

Q11：new Location(player.getWorld(), x, y, z) 做了什么？

Location 是 Bukkit 中的坐标对象，包含世界（World）和三维位置 (X, Y, Z)。这里创建了一个三维坐标，用于在特定位置生成实体。

Q12：player.getWorld().spawnEntity(location, entityType) 是什么？

调用 Bukkit API，在指定位置创建某种实体对象。这是命令的核心功能，也就是定义了具体生成实体的方法。

Q13：为什么有时返回 true，有时 false？

在 Bukkit 命令系统中：
true = 命令执行完毕，不显示帮助提示。
false = 命令格式错误，Bukkit 自动显示 /命令 使用方式 (Usage)。
这是接口 CommandExecutor 的协议要求。

Q14：为什么 onTabComplete 要返回 List<String>？

Bukkit 会使用这个返回列表作为命令补全选项列表，用户在输入命令时看到。

Q15：switch (args.length) 是什么结构？

Java 的多分支控制结构，用来根据不同的参数数量执行不同提示逻辑。
case 1: 表示用户输入第一个参数时进入实体补全；
case 2: 表示第二个参数时提供玩家名或坐标选项。以此类推...

Q16：为什么对 EntityType.values() 使用循环？

EntityType 是一种枚举类型（Enum），我们在输入"EntityType."之后会提示我们其内部定义的所有实体类型，例如 COW、PIG、ZOMBIE、CREEPER 等除玩家外所有具体实体，而 values() 返回枚举中所有常量（所有实体类型）。循环中筛选出可生成（isSpawnable）、可存活（isAlive）的实体，再匹配开头添加进候选结果。

Q17：new ArrayList<>() 和 Collections.emptyList() 的区别？

两者都是返回一个列表对象：
new ArrayList<>() 可修改；
Collections.emptyList() 是一个不可修改、共享的空集合。
后者更高效，适合只读结果。

Q18：toLowerCase 和 toUpperCase 是什么？

这是 Java 中 String 字符串的 2 种处理方法。我们很容易理解我们输入的指令被当作字符串（String）处理，包括但不限于文本解析、文本提取。而在 Bukkit 的 EntityType 中所有的实体枚举都是大写，进行自动转换可以正确获取枚举，并且自动将我们不严格的输入处理成正确的全大写格式。例如我们输入 /spawnentity zOmbIE，此转换可以正确理解为生成 ZOMBIE，避免出现内部错误。

Q19：为什么类中既有命令逻辑又有补全逻辑而不分开？

这样设计方便管理，一个命令的执行与补全放在同一个类中，实现一致性和可维护性。不过在大型项目中，也可拆为 Executor 与 Completer 独立类。

Q20：返回 false 时提示信息从哪里来？

plugin.yml 文件中命令配置的 usage 字段定义了帮助提示内容。例如：

plugin.yml
commands:
  spawnentity:
    description: 生成一个实体
    usage: /spawnentity <实体名> <玩家|x y z>

因此在没有额外设计的情况下 return false 会让 Bukkit 返回这行信息提示我们。

Q21：这种多层逻辑结构体现了哪些编程理念？

封装 (Encapsulation)：所有命令逻辑集中在类内部。
健壮性 (Robustness)：各种输入错误均通过异常捕获或条件检查处理。
可扩展性 (Extensibility)：新实体或命令参数可以轻松加入无需修改核心框架。
